# V1.4.7 · 外部职场内容增量优化（在Excel交付后触发）

## 触发与用户体验

已完成一轮 `finalize` 并交付 Excel 后，Skill 在聊天末尾**加粗**提示：

> **📌 在小红书看到职场好文，可以在评论区“@点点给我逐字稿”，直接把点点的总结或逐字稿贴过来。我会结合你的画像和筛选出的JD继续优化这份Excel～**

后续用户粘贴**任何自己有权提供的**职场文字（不必来自小红书，也不要求连接点点或实际联网）。默认识别其关键行动建议，与**本次运行 profile.json、对应 JD全文与已有岗位评分**合并研判。

1. **识别主题**，例如面试反向提问、薪酬核实、真实职责验证、岗位卡点、项目经验包装、技能学习。找不到可靠落点时先提具体的改进建议，不硬生成列。
2. **检查Excel现有列**：如果有等价列，直接提出并写回对应岗位；只存在**相关但语义较宽**的列时，先展示“沿用已有列”与“增加新列”两种选择，确认后执行；不存在等价列则**先问用户是否新增**。
3. **按岗位优先级处理**：默认分析4–5分岗位中的前10个，必要时可以扩大到100个，或者用户指定评分区间；不要默默对2万行调用模型。如果用户想更新全部岗位，须先就范围和成本取得同意。
4. **建立证据链**：从JD职责、技能、当前卡点及个人画像中找与新知识匹配的信息。明确标注“依据JD建议反问”与“候选人真实已做项目”，绝不把推断当作公司内幕，也不臆造候选人经历。
5. **只写派生建议**：禁止修改推荐等级、红线、JD原始文字、JD全文、图片、来源字段或分数；原始两列“卡点判断/卡点如何解决”若用户指定更新可用 append 模式保留旧内容。
6. **只交付结果**：成功后读取本次 `<run>/learning_summary.md`，在聊天给用户一段简洁总结和**同一份更新后的 Excel**。不默认交付草稿JSON或逐字稿备份。

## 示例：用户粘贴「噜噜oni」面试反向提问分享

输入内容提到四类核实重点：①HC来源/招聘多久；②组织架构、直属上级与分工；③真实工作职责、招聘关键词与以往筛选门槛；④固定薪酬、月数、绩效奖金和浮动部分。

Agent应根据本轮JD而不是直接抄四类文字：

- 有 Agent/AI 应用职责：优先问**入职90天要落地什么业务、效果指标/质量红线是什么**；问业务落地及验证流程。
- 有 Java/C++/算法关键词，但本人画像红线包含这类职责：优先问**真实日常工作中Agent/后端/算法的占比**，识别名为“AI”实为其他工作的岗位。
- JD写“评测/稳定性”：优先问**有没有真实评测集、验收标准、线上反馈与故障处理责任**。
- 在任何岗位都可核对“HC是新增还是替补、团队组织、HR筛选关键词、薪资结构”；但这些是**建议向HR提问**，不是JD已经证明的内部事实。

默认建议列 **「面试反向提问」**。如果当前表只有「待确认条件」，这是宽泛相关列：让用户确认要不要直接复用「待确认条件」；不应自作主张认为语义完全等价。若用户坚持复用原「卡点判断」，仅在该列末尾补充一个清晰标记的建议，不覆盖原始判断。

## 可执行命令

```bash
# Agent先把用户给的总结/逐字稿保存成run目录下notes.txt（UTF-8）
python scripts/run.py learn-preview \
  --run-dir ./run \
  --text-file ./run/notes.txt \
  --creator '噜噜oni' \
  --min-score 4 --limit 10
```

该命令不改变Excel，返回：

- `suggested_column`：建议目标列；`existing_column`：Excel中已存在的等价列（可能为空）；
- `related_existing_columns`：语义相近但不等价的列，供用户选择；
- `requires_new_column_confirmation`：新增列是否需要用户确认；
- `sample_jobs`：初步关联的高分岗位和优先提问方向；
- `draft`：输出的 `learning_draft.json` 路径，供Agent按JD与画像完善逐岗位建议。

`learning_draft.json` 主要结构：

```json
{
  "source": {"kind":"user_shared_career_content", "creator":"噜噜oni", "sha256":"<64位SHA256>", "topic":"interview_questions"},
  "target_column": "面试反向提问",
  "updates": [
    {"item_id":"IMG-002", "column":"面试反向提问", "value":"【优先反问】...", "mode":"append", "jd_evidence":"", "profile_evidence":""}
  ],
  "summary":"本次已识别内容的建议主题与应用范围"
}
```

- `jd_evidence` 是可选的**逐字子串**。若提出“该岗位当前内部就存在某项问题”，则必须给出可验证证据，否则降级为“向HR核实”而非陈述事实。
- `profile_evidence` 必须能从用户已明确提供的经历/技能中找到；程序不会把它直接当作评分规则。
- `value` 用新内容改写的建议要与岗位需求成对。模型识别不出对应关系时留空，不要为了填满所有岗位而编造。
- 建议列默认仅填选中的高分岗位；没更新的行保持空白（新列）或原文（旧列）。

写回：

```bash
# ① Excel 已有等价列（无需额外确认，用户已明确要求用新内容优化）
python scripts/run.py learn-apply --run-dir ./run --file ./run/learning_draft.json

# ② 新列（只在用户明确同意新增之后）
python scripts/run.py learn-apply --run-dir ./run --file ./run/learning_draft.json --confirm-new-column
```

**注意：** 模型可能写出内容，但未经明确用户同意时，不能借参数 `--confirm-new-column` 自动加列。只对当前 `summary.json` 指向的 Excel 修改；其它来源的普通Excel不自动覆盖。若源目录丢失，应由用户重新提供其工作簿并建立可以核对的岗位编号映射，而不是凭名称猜测关联。

## 写回保证与断点续跑

- 根据 Excel 的「图片编号」而不是当前行号更新（排序后也不串行）；保存 `learning_updates.json`（已确认的更新）和 `learning_summary.md`（仅供聊天展示）。
- 再次收到同一条摘要，不会重复附加同样文字；同一个 run 再 `finalize`，会重新应用已保存的改动，不重跑 OCR/JD/评分。
- 修改 Excel 用临时文件加 `os.replace` 原子替换，原有图片与冻结 D2 保留；代码检查分数列在写回前后完全一致。
- 对超大工作簿，增量更新仍需要一次Excel重新保存，会有实际文件I/O时间；但**不需要重新计算26,777条岗位评分**。
- 若用户明确要求把新想法纳入“未来每批都使用的通用评分原则”，那属于**评分策略变更**，要先单独确认、做跨画像回归，并更新参考文档；不能用一次性Excel建议悄悄改动后续评分。
