# 用户反馈驱动迭代记录｜User Feedback → Product Change → Evidence

> 本记录基于作者在小红书收到的**三条用户评论**及既有真实工程复盘。三条评论仅代表个别反馈，不是代表性用户调查。对未上线功能、未验证收益，不写“已提升准确率”。项目不展示评论者的个人信息。

## 2026-11｜案例 F-01：自动化不能代替自主判断

**用户原话**：「自动化是好，风险也大，不如老老实实自己搞」。

- **需求假设**：用户可能担心AI误排好岗位、失去核验依据，宁愿慢一点自己看。尚未做访谈确认此假设。
- **设计判断**：仅宣传快不够；需要让低分岗位的存疑处浮到表面，同时不随意推翻清楚命中硬红线的评分。
- **V1.4.8 实现**：`scripts/opportunity_audit.py` 在**原有评分之后**根据经验冲突、职责匹配不确定、待核实条件、JD歧义生成「低分复核」工作表和聊天提醒；硬性红线已有可追溯证据时保持排除，不自动改分；`audit` 可独立复查已有运行。
- **可复现验证**：`evals/test_feedback_v148.py` 包括“硬红线不误推荐”“不确定低分进入复核”“推荐等级C列不改”“大表快速导出不丢复核表”。**需要真实用户后续测试复核提醒是否真正减少误杀**。

## 2026-11｜案例 F-02：这工具是不是在卖信息？

**用户原话**：「这种工具卖信息」。

- **需求假设**：可能是担心资料被售卖或不理解信息加工价值；该短句有歧义，不能擅自认定为隐私指控。
- **设计判断**：公开区分“用户自行提供的JD信息”和“Skill提供的证据化决策、技能覆盖、误杀复核”。
- **V1.4.8 实现**：README新增《数据如何流转》与信任说明；欢迎页用一句话指出Skill不提供付费招聘信息、不替用户自动投递，使用本地 OCR 或平台原生模型时的数据处理边界不同；`learn-preview` 将此类反馈路由为解释，不自动为Excel添加无关列。
- **可复现验证**：文档和路由测试。**没有独立隐私审计，不宣称平台或上游模型绝不存储数据。**

## 2026-11｜案例 F-03：让适合的老板看见我的能力

**用户原话**：「还有一种，可以发表自己的想法让老板找上门[偷笑R]」。

- **需求假设**：除主动筛岗位，部分用户也希望通过项目、观点与作品提高被招聘团队主动发现的机会。
- **设计判断**：不自动发布或替用户编造项目成绩。把**高分岗位共同需求**与**个人已确认技能、画像自述项目**对应起来，推荐有证据可展示的作品主题。
- **V1.4.8 实现**：`showcase --run-dir ...` 读取已交付的 `skill_insights.json` 和 `profile.json`，输出最多5个选题及JD证据、个人能力证据等级、表达形式与下一步验证；用户明确要求时才执行。
- **可复现验证**：测试“只能引用原JD技能证据”“缺能力证据不捏造”“不修改历史评分与Excel”。**不承诺产生内推、联系或Offer。**
